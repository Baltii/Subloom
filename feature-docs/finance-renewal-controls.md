# Bitcoin wallets, history, and renewal preferences

Settings → Cards & transactions → Bitcoin wallets & payments. Save up to twenty Bitcoin mainnet SegWit/Taproot public watch addresses, validated with BIP 173/350 checksums. No signing keys, seed phrases or wallet credentials are stored. Watching an address does not prove ownership or expose every address in a wallet.

Refresh retrieves the latest 25 address transactions from the open-source mempool/Esplora API. Clients validate payload size, amounts, IDs, confirmation fields and address relevance. Net satoshi movement includes change/fees and is kept separately from manually recorded fiat spending and subscription forecasts. Observations are provider-reported, not independently cryptographically verified, and can change after chain reorganizations. Guests persist observations on device; account histories are stored by an authenticated, rate-limited Edge Function in a read-only owner-isolated table. Guests explicitly refresh directly; account deployments can configure an HTTPS self-hosted explorer with BITCOIN_EXPLORER_URL. The UI explains that refreshing shares the public address with the explorer. All guest data and account observations participate in reset/export/account deletion.

Pay with Bitcoin creates an exact bitcoin: payment URI after validating the destination and integer satoshi amount. A review step displays recipient and amount before opening an external wallet. The wallet authorizes and sends, including network fees. Subloom does not sign/broadcast, fabricate transaction success, or infer a subscription renewal from opening a wallet. No real funds were sent in testing.

Renewal controls save a review date and intention (review/renew/cancel) for an owned subscription. These are explicitly preferences: no automated job, notification or merchant action is scheduled. Automatic card/Apple/Google billing, cancellation of external merchant subscriptions, crypto autopay and BTCPay merchant checkout are NOT implemented in this stack. A compatible merchant billing integration, hosted BTCPay store if applicable, and a payer mandate remain prerequisites. BTCPay is an open-source option, not a universal cancellation API; hosting and Bitcoin network fees remain external costs.
